## Bus Topology

### 1. What is Bus Topology?
Bus Topology is a network topology in which all devices are connected to a single main cable, called the **Backbone Cable**.
In simple words, imagine multiple computers connected to one common cable. All computers use that cable to communicate with each other.

**Example:**
Imagine a computer laboratory has five computers.
Instead of connecting every computer to a separate switch, all five computers connect to one main cable.
That main cable is called the **Backbone Cable**.

### 2. How Does Bus Topology Work?
Let's understand step by step.
Imagine Computer A wants to send data to Computer D.

1. Computer A sends data through the main cable.
2. The data travels along the backbone cable.
3. Other connected computers can detect the transmitted signal.
4. Computer D checks the destination address and accepts the data.
5. Other computers ignore the data because it is not addressed to them.

**Important:** Traditional shared-medium Ethernet bus networks use a technology called **CSMA/CD** to manage access to the shared cable.

### 3. Important Components of Bus Topology

| Component | Purpose |
|-----------|---------|
| Backbone Cable | Main cable connecting all devices. |
| Terminator | Prevents signals from reflecting back at the ends of the cable. |
| Network Interface Card (NIC) | Allows a computer to connect to the network. |
| BNC Connector | Used to connect devices to coaxial cable in traditional bus networks. |

**What is a Terminator?**
A terminator is a component placed at both ends of the backbone cable.
Its purpose is to absorb signals and prevent them from reflecting back along the cable.
Without proper termination, reflected signals can interfere with network communication.

### 4. Advantages of Bus Topology
- Easy to understand.
- Requires less cable than some other topologies.
- Simple to set up in small networks.
- Does not require a central switch.
- Can be inexpensive for small installations.

### 5. Disadvantages of Bus Topology
- If the main backbone cable fails, the entire network can stop working.
- Network performance can decrease when many devices communicate.
- Troubleshooting cable problems can be difficult.
- Limited cable length and number of connected devices.
- Traditional shared-medium networks can experience collisions.

### 6. Bus Topology and Cybersecurity
Bus topology is useful to understand because all connected devices share the same communication medium.
For example:
- **Packet Sniffing:** A device connected to the shared medium may be able to observe traffic transmitted across it.
- **Collisions:** Multiple devices transmitting at the same time can cause collisions in traditional shared Ethernet.
- **Network Failure:** Damage to the backbone cable can interrupt communication for all devices.

## Star Topology

### 1. What is Star Topology?
Star Topology is a network topology in which every device is connected to one central networking device.
This central device is usually a network switch.
All devices communicate through this central device.
It is called Star Topology because its structure looks like a star, with the central device in the middle and connected devices around it.

**Simple example:**
Imagine a computer lab with 10 computers. Instead of connecting all computers directly to each other, we connect every computer to one central switch.
Now, all computers can communicate through that switch.

### 2. How does Star Topology work?
Let's understand with an example:
- PC1 wants to send data to PC2.
- PC1 sends the data to the central switch.
- The switch checks the destination MAC address.
- The switch forwards the data through the port connected to PC2.
- PC2 receives the data.

**Important:** A network switch uses its MAC address table to decide which port should receive the frame.

### 3. Main Components

| Component | Purpose |
|-----------|---------|
| Central Switch | Connects all network devices |
| Ethernet Cable | Connects devices to the switch |
| NIC | Allows a device to connect to the network |
| Network Devices | Computers, printers, servers, etc. |

### 4. What happens if a cable or switch fails?
This is one of the most important concepts in Star Topology.

**Scenario 1: One cable fails**
Suppose the cable connected to PC1 gets damaged.
- PC1 loses network connectivity.
- Other devices can continue communicating.
- The entire network does not stop.

**Scenario 2: Central switch fails**
Suppose the central switch stops working.
- All connected devices lose network connectivity through that switch.
- Communication between those devices stops.
- The network can become completely unavailable.

This makes the central switch a potential **Single Point of Failure (SPOF)**.
We will study SPOF separately later.

### 5. Advantages of Star Topology
1. Easy to install and manage.
2. Easy to identify network problems.
3. Failure of one cable usually affects only one device.
4. Devices can be added or removed easily.
5. Good performance with modern switches.
6. Commonly used in modern Ethernet networks.

### 6. Disadvantages of Star Topology
1. If the central switch fails, connected devices lose connectivity.
2. Requires more cables than Bus Topology.
3. Requires a central networking device.
4. Larger networks may need multiple switches.
5. Switches and cabling increase installation costs.

### 7. Star Topology in Real-World Networks
Star Topology is commonly used in:
- Home networks.
- Office networks.
- Computer labs.
- School and college networks.
- Small and medium-sized enterprise networks.

For example, in an office:
- 20 computers connect to a switch.
- 2 printers connect to the same switch.
- 1 server connects to the same switch.
- The switch connects to a router for internet access.

All these devices communicate through the network infrastructure.

## Ring Topology

### 1. What is Ring Topology?
Ring Topology is a network topology in which each device is connected to two neighboring devices, forming a closed loop.
In simple words:
- Every device has two neighbors.
- The last device connects back to the first device.
- Together, all devices form a circular network.

It is called Ring Topology because the network looks like a ring.

### 2. How does Ring Topology work?
Let's understand with an example.
Suppose we have four computers:
- PC1
- PC2
- PC3
- PC4

They are connected in a circular structure:
Suppose PC1 wants to send data to PC3.
In a traditional ring network:
1. PC1 sends data to its neighboring device, PC2.
2. PC2 forwards the data to PC3.
3. PC3 receives the data.
4. The data continues around the ring or is removed according to the network technology.

**Important:** Data may travel in one direction or, in some ring technologies, in both directions.

### 3. What is Token Passing?
Token Passing is a method used by some traditional ring networks to control which device can send data.
A small special frame called a **token** circulates around the network.
Let's understand:
1. A token continuously moves around the ring.
2. A device must receive the free token before sending data.
3. The device takes control of the token and sends its data.
4. After transmission, the token becomes available again.
5. Another device can use it.

**Example:** Suppose PC1 wants to send data to PC3. PC1 waits until it receives the free token. Once it gets the token, it can transmit its data.

This method helps control access to the shared network and avoids collisions in traditional token-passing systems.

**Note:** Token Passing was used in technologies such as IBM Token Ring. Not every modern ring network uses token passing.

### 4. What happens if one connection fails?
This is an important limitation of a basic Ring Topology.
Suppose the connection between PC2 and PC3 breaks.
- The circular path is interrupted.
- Data may not be able to reach other devices.
- The entire basic ring network may stop working.

However, some advanced ring networks use protection mechanisms, such as a secondary ring or automatic path recovery, to maintain communication when a link fails.

### 5. Advantages of Ring Topology
1. Data transmission can be organized through a controlled process.
2. Token Passing can prevent collisions.
3. Each device gets an opportunity to transmit.
4. Network traffic can be predictable in traditional token-based systems.

### 6. Disadvantages of Ring Topology
1. A single link or device failure can interrupt a basic ring.
2. Adding or removing devices can disrupt the network.
3. Troubleshooting can be difficult.
4. Data may pass through multiple devices before reaching its destination.
5. Ring maintenance can be more complicated than a basic star network.

### 7. Real-World Applications
Traditional Ring Topology was used in:
- IBM Token Ring networks.
- FDDI (Fiber Distributed Data Interface).
- Some telecommunications and industrial network designs.

## Mesh Topology: Full Mesh vs Partial Mesh

### 1. What is Mesh Topology?
Mesh Topology is a network topology in which devices are connected to multiple other devices through separate network links.
Unlike Star Topology, where devices depend on a central switch for communication, Mesh Topology provides multiple possible paths between devices.
The main purpose of Mesh Topology is to improve network reliability and availability.

Let's understand with an example.
Suppose an organization has four offices:
- Office A
- Office B
- Office C
- Office D

If these offices are connected through multiple network links, they may still communicate even if one link fails.
This is one of the biggest advantages of Mesh Topology.

### 2. Types of Mesh Topology
There are two main types:
1. Full Mesh Topology
2. Partial Mesh Topology

Let's understand them separately.

### 3. Full Mesh Topology
In Full Mesh Topology, every device has a direct connection to every other device.
For example, suppose we have four routers:
- Router A
- Router B
- Router C
- Router D

In Full Mesh:
- Router A connects directly to B, C and D.
- Router B connects directly to A, C and D.
- Router C connects directly to A, B and D.
- Router D connects directly to A, B and C.

Every router has a direct connection to all the other routers.

**How many connections are required?**

So, four routers require six direct connections in a Full Mesh.

**What happens if one connection fails?**
Suppose the direct connection between Router A and Router B fails.
- Router A can still communicate with Router B through Router C or Router D, assuming the remaining paths are operational and routing is configured.
- The network can continue working.
- Multiple paths provide redundancy.

This makes Full Mesh highly reliable.

### 4. Partial Mesh Topology
In Partial Mesh Topology, only some devices have direct connections to each other.
Not every device is directly connected to every other device.
For example:
- Router A connects directly to B and C.
- Router B connects directly to A and C.
- Router C connects to A, B and D.
- Router D connects directly to C.

Here, some routers have multiple connections, while others have fewer connections.

**What happens if one connection fails?**
Suppose the connection between Router A and Router C fails.
If another working path exists, Router A may communicate with Router C through Router B.
However, if no alternative path exists, communication may stop.
So, Partial Mesh provides redundancy where alternative paths are designed, but not necessarily between every pair of devices.

### 5. Full Mesh vs Partial Mesh

| Feature | Full Mesh | Partial Mesh |
|---------|-----------|--------------|
| Connections | Every device connects to every other device | Only selected devices are directly connected |
| Reliability | Very high | Depends on available alternative paths |
| Cost | High | Lower than Full Mesh in many designs |
| Installation | Complex | Comparatively easier |
| Redundancy | Extensive | Selective |
| Scalability | Expensive as devices increase | More flexible in many designs |

### 6. Advantages of Mesh Topology
1. Provides multiple communication paths.
2. Improves network reliability.
3. Can continue working after some link failures.
4. Reduces dependence on a single communication path.
5. Useful for networks that require high availability.

### 7. Disadvantages of Mesh Topology
1. Requires more cables and network interfaces.
2. Installation can be expensive.
3. Configuration and maintenance can be complex.
4. Full Mesh becomes difficult to scale because connections increase rapidly.
5. Troubleshooting multiple network paths can be challenging.

### 8. Real-World Applications
Mesh Topology is used in different environments:
- Enterprise WAN connections.
- Data center networks.
- Wireless mesh networks.
- Telecommunications networks.
- Networks requiring high availability.

For example, a company may connect its Delhi, Mumbai and Bangalore offices through multiple WAN links.
If one link fails, network traffic may use another available route.

**Note:** A network can use a partial mesh design rather than connecting every office directly to every other office.

## Tree Topology

### 1. What is Tree Topology?
Tree Topology is a network topology in which devices are connected in a hierarchical structure, similar to the branches of a tree.
It combines multiple Star Topologies into one larger network.
In simple words:
- One main device connects to other networking devices.
- Those devices connect to more devices.
- The network grows in different levels or branches.

This structure is commonly used in large organisations.

### 2. How does Tree Topology work?
Let's understand with an office example.
Suppose a company has three departments:
- HR Department
- IT Department
- Finance Department

The company uses a hierarchical network structure.
The structure works like this:

**Level 1 — Core Switch**
The core switch acts as the main connection point for the network.

**Level 2 — Department Switches**
The core switch connects to different department switches.
For example:
- HR Switch
- IT Switch
- Finance Switch

**Level 3 — End Devices**
Each department switch connects to computers, printers and other devices.
For example, HR computers connect to the HR switch.
This creates a hierarchical network structure.

### 3. Understanding the Hierarchical Levels
In enterprise networks, you may see three common layers:

| Layer | Purpose |
|-------|---------|
| Core Layer | Provides high-speed connectivity between major network sections |
| Distribution Layer | Connects access switches and applies network policies |
| Access Layer | Connects end devices such as computers and printers |

**Easy way to remember:**
- Core = Main network backbone.
- Distribution = Connects and manages network sections.
- Access = Connects users and devices.

Not every network needs all three layers. Smaller networks may combine these functions.

### 4. What happens if a device or connection fails?
Let's understand two scenarios.

**Scenario 1: One computer connection fails**
Suppose one computer's cable gets damaged.
- That computer loses connectivity.
- Other computers can continue working.
- The entire network does not stop.

**Scenario 2: Department switch fails**
Suppose the HR department switch stops working.
- HR computers connected to that switch may lose network access.
- IT and Finance departments can continue working.
- The impact is limited to the affected branch, assuming the rest of the network is operational.

**Scenario 3: Core switch fails**
Suppose the main core switch fails.
- Multiple departments may lose connectivity.
- Communication between different network sections may stop.
- A large part of the network may become unavailable.

This shows why the central or upper layers of a hierarchical network are important.

### 5. Advantages of Tree Topology
1. Easy to expand by adding new branches.
2. Suitable for large organizations.
3. Supports hierarchical network management.
4. Problems can often be isolated to a particular branch.
5. Departments can have separate network sections.
6. Makes network organization easier.

### 6. Disadvantages of Tree Topology
1. Failure of an important upper-level device can affect multiple branches.
2. Requires more networking devices and cables.
3. Installation and maintenance can be expensive.
4. Configuration can become complex as the network grows.
5. Requires careful planning to avoid bottlenecks.

### 7. Real-World Applications
Tree Topology or hierarchical network designs are commonly used in:
- Corporate office networks.
- Universities and colleges.
- Hospitals.
- Large enterprise networks.
- Campus networks.
- Multi-floor office buildings.

**Example:**
A university may have:
- One main core switch.
- Separate switches for different buildings.
- Additional switches for classrooms and laboratories.
- Computers and printers connected to access switches.

## Hybrid Topology

### 1. What is Hybrid Topology?
Hybrid Topology is a network topology that combines two or more different network topologies into a single network.
For example, an organization may combine:
- Star Topology
- Bus Topology
- Mesh Topology
- Tree Topology

The purpose is to build a network that meets the organization's requirements.
In simple words, instead of using only one topology, we combine different topologies to create a larger network.

### 2. How does Hybrid Topology work?
Let's understand with an example of a large company.
Suppose a company has three departments:
- HR Department
- IT Department
- Finance Department

Each department has its own Star Topology, where computers connect to a central switch.
These department switches are connected through a larger hierarchical network.
Here is how it works:
1. Computers in the HR department connect to an HR switch.
2. Computers in the IT department connect to an IT switch.
3. Computers in the Finance department connect to a Finance switch.
4. These switches connect to the company's main network infrastructure.
5. Devices from different departments can communicate through the network.

This is an example of a Hybrid Topology because different network structures work together.

### 3. Examples of Hybrid Topology

**Example 1: Star + Tree**
- Computers connect to individual switches using Star Topology.
- Multiple switches connect through a hierarchical structure.
- The overall network follows a Tree structure.

This is common in enterprise networks.

**Example 2: Star + Mesh**
- Computers connect to local switches using Star Topology.
- Important switches or locations connect through multiple paths using Mesh Topology.
- If one inter-switch connection fails, another path may be available.

This design can improve network availability.

### 4. What happens if a device or connection fails?
Let's understand with an office example.
Suppose an organization uses a Hybrid Topology with multiple department switches.

**Scenario 1: One computer cable fails**
- Only that computer loses connectivity.
- Other computers can continue working.

**Scenario 2: One department switch fails**
- Devices connected to that switch may lose connectivity.
- Other departments may continue working.

**Scenario 3: Main network connection fails**
- Communication between different departments may be interrupted.
- Local communication within a department may still work, depending on its network design.

The actual impact depends on how the different topologies are connected.

### 5. Advantages of Hybrid Topology
1. Flexible network design.
2. Suitable for large organizations.
3. Can combine the advantages of different topologies.
4. Easy to expand when properly designed.
5. Can provide redundancy and better availability.
6. Different departments can use different network structures.

### 6. Disadvantages of Hybrid Topology
1. Network design can become complex.
2. Installation costs can be high.
3. Requires proper planning.
4. Troubleshooting can be difficult.
5. Maintenance may require specialized networking knowledge.

### 7. Real-World Applications
Hybrid Topology is commonly used in:
- Large corporate networks.
- Universities and colleges.
- Hospitals.
- Data centers.
- Enterprise networks.
- Multi-building campus networks.

**Example:**
A university may use Star Topology inside individual computer labs and connect different buildings through a redundant network infrastructure.
Together, these different network structures form a Hybrid Topology.

## Physical Topology vs Logical Topology

This is an important networking concept because Physical Topology and Logical Topology describe two different things about the same network.

### 1. What is Physical Topology?
Physical Topology describes how network devices are physically connected to each other.
It shows the actual arrangement of:
- Computers
- Switches
- Routers
- Network cables
- Access points
- Other networking devices

In simple words, Physical Topology tells us how the network is physically built.

**Example: Physical Star Topology**
Suppose an office has five computers connected to one central switch using Ethernet cables.
This is a Physical Star Topology because all computers have separate physical cable connections to the central switch.

### 2. What is Logical Topology?
Logical Topology describes how data travels between devices across a network.
It focuses on the communication path and how devices access and exchange data.
In simple words, Logical Topology tells us how devices communicate over the network.

For example:
Suppose PC1 wants to send data to PC3.
- PC1 generates a data frame.
- The network forwards the frame through the appropriate communication path.
- PC3 receives the data.

Logical Topology focuses on how this communication happens, not simply where the cables are connected.

### 3. Physical vs Logical Topology — Main Difference

| Physical Topology | Logical Topology |
|-------------------|------------------|
| Shows the actual physical connections between devices. | Shows how data is transmitted between devices. |
| Describes physical connections | Describes data communication |
| Focuses on cables and devices | Focuses on data flow |
| Shows network layout | Shows communication behavior |
| Helps with installation | Helps understand data transmission |

### 4. Can Physical and Logical Topologies Be Different?
**Yes!** This is the most important point.
A network can have one physical topology but a different logical topology.
Let's understand with an example.

**Example: Hub-Based Ethernet Network**
Suppose five computers are connected to one central Ethernet hub.

**Physically:**
- Every computer has a separate cable.
- All cables connect to the central hub.
- The physical structure looks like a Star.

**Logically:**
- A traditional Ethernet hub repeats incoming signals to all other ports.
- Devices share the same communication medium.
- The logical communication behaves like a Bus.

Therefore:
**Physical Star**
**Logical Bus**

This is a classic example of how physical and logical topologies can differ.

**Important:** This is a traditional hub-based Ethernet example. Modern switched Ethernet normally uses physical Star or hierarchical Star arrangements with point-to-point links.

### 5. Another Example: Modern Switch-Based Network
Suppose four computers are connected to a modern Ethernet switch.

**Physically:**
- Every computer connects separately to the switch.
- The physical topology is Star.

**Logically:**
- The switch forwards frames based on destination MAC addresses.
- Each Ethernet link is a separate point-to-point connection.
- Communication between devices is handled through switching.

This is different from the shared-medium behavior of an old Ethernet hub.

## Single Point of Failure (SPOF)

### 1. What is a Single Point of Failure?
SPOF stands for **Single Point of Failure**.
A Single Point of Failure is a component in a system or network whose failure can cause the entire system or an important part of it to stop working.

In simple words:
Imagine an office where 50 computers are connected to one central network switch.
All computers depend on that switch for network communication.
Now, suppose that switch suddenly stops working.
- All 50 computers may lose network connectivity.
- Employees may not be able to access internal servers.
- Network services may become unavailable.

Here, the central switch is a Single Point of Failure.
Why?
Because one component failing can affect the entire connected network.

### 2. Real-World Examples of SPOF
Let's understand some common examples.

**Example 1: Central Network Switch**
Suppose an office has:
- 30 computers
- 2 printers
- 1 server

All devices connect through one central switch.
If the switch fails, all connected devices may lose network connectivity.
**SPOF:** Central switch.

**Example 2: Single Router**
Suppose a company uses only one router to connect its office network to the internet.
If that router fails:
- Employees may lose internet access.
- Cloud applications may become unavailable.
- Remote services may become unreachable.
**SPOF:** Single router.

**Example 3: Single Internet Connection**
Suppose a company has only one ISP (Internet Service Provider).
If that ISP has an outage:
- The company may lose internet connectivity.
- Employees may be unable to access external services.
- Cloud-based applications may become unavailable.
**SPOF:** Single internet connection.

**Example 4: Single Firewall**
Suppose a company has only one firewall between its internal network and the internet.
If the firewall fails and there is no failover device:
- Network traffic may be interrupted.
- Internet access may stop.
- Security inspection may become unavailable.
**SPOF:** Single firewall.

### 3. Why is SPOF Dangerous?
A Single Point of Failure creates dependency on one component.
If that component fails, the impact can be very large.
Some possible consequences:
1. Network downtime.
2. Business interruption.
3. Loss of access to important services.
4. Financial losses.
5. Reduced productivity.
6. Security monitoring interruptions.

**Example:**
Suppose a hospital uses one central network switch for important medical systems.
If that switch fails, access to some important network services may be interrupted.
This is why organizations try to identify and reduce Single Points of Failure.

### 4. How Can We Prevent SPOF?
The main solution is to introduce **Redundancy**.
Redundancy means having additional components or alternative paths available when the primary component fails.
Let's understand.

**Without Redundancy**
- One router.
- One internet connection.
- If the router fails, connectivity stops.

**With Redundancy**
- Two routers.
- Two network paths.
- Primary and backup connections.
- If one router or connection fails, another may take over.

This can reduce the risk of network downtime.

**Important:** Simply installing a backup device is not enough. It must be properly configured so that traffic can switch to it when needed.

### 5. Common Network Components That Can Become SPOFs

| Component | Possible Impact |
|-----------|-----------------|
| Central Switch | Connected devices lose network connectivity |
| Core Router | Multiple network sections may lose connectivity |
| Firewall | Network traffic may be interrupted |
| ISP Connection | Internet connectivity may stop |
| DNS Server | Domain name resolution may fail |
| DHCP Server | Devices may face problems obtaining IP addresses |
| Power Supply | Network equipment may shut down |

Whether a component is actually an SPOF depends on the network design and available backups.

## Redundancy, Fault Tolerance and Scalability

These three concepts are very important in enterprise networking, network architecture and SOC operations.
They are related, but **Redundancy**, **Fault Tolerance** and **Scalability** have different meanings.
Let's understand them one by one.

### 1. What is Redundancy?
Redundancy means having additional components, connections or resources available as backups.
In simple words, if one component fails, another component is available to take its place.

**Example: Network Router**
Suppose a company has only one router.
If this router fails, the company may lose internet connectivity.
Now suppose the company installs two routers:
- Router 1 = Primary Router
- Router 2 = Backup Router

If Router 1 fails, Router 2 can take over if failover is configured.
This is called Redundancy.

**Types of Network Redundancy**
1. **Hardware Redundancy:** Having backup routers, switches, firewalls or power supplies.
2. **Link Redundancy:** Having multiple network connections or paths.
3. **Power Redundancy:** Having backup power supplies or UPS systems.
4. **Internet Redundancy:** Using multiple ISP connections.

Remember: Redundancy means having a backup available.

### 2. What is Fault Tolerance?
Fault Tolerance is the ability of a system to continue operating even when one or more components fail.
In simple words, the system continues working even after a failure.

**Example: Two Network Connections**
Suppose a company has two network links:
- Link 1 = Primary
- Link 2 = Backup

Now imagine Link 1 fails.
What happens?
1. The network detects the failure.
2. Traffic switches to Link 2, if automatic failover is configured.
3. Users can continue accessing network services.

This is an example of Fault Tolerance.

**Important Difference**
Let's understand the relationship:
- **Redundancy** = Backup components are available.
- **Fault Tolerance** = The system continues operating despite failures.

**Example:**
Installing a second router provides redundancy.
Configuring the network so the second router automatically takes over when the first router fails helps provide fault tolerance.
A backup component alone does not guarantee fault tolerance. Proper configuration is also required.

### 3. What is Scalability?
Scalability is the ability of a network or system to grow and handle increasing requirements without requiring a complete redesign.
In simple words, scalability means the network can expand as an organisation grows.

**Example: Growing Company**
Suppose a company initially has:
- 10 employees.
- 10 computers.
- 1 network switch.

After one year, the company grows.
Now it has:
- 100 employees.
- 100 computers.
- Multiple departments.

The network needs to support more devices and increased traffic.
A scalable network allows the organisation to add switches, network links, IP address capacity and other resources as required.

**Types of Scalability**
1. **Horizontal Scalability**
   Adding more devices or components to increase capacity.
   Example:
   - Adding more network switches.
   - Adding more servers.
   - Adding additional network paths.

2. **Vertical Scalability**
   Increasing the capacity of existing hardware.
   Example:
   - Upgrading a router to a higher-capacity model.
   - Increasing server RAM.
   - Upgrading CPU or processing capacity.

### 4. Redundancy vs Fault Tolerance vs Scalability
This is the most important comparison.

| Concept | Meaning | Main Purpose |
|---------|---------|--------------|
| Redundancy | Having backup components | Backup availability |
| Fault Tolerance | Continuing operation during failures | Service continuity |
| Scalability | Ability to handle growth | Future expansion |

**Easy Real-World Example**
Imagine you own a company.
- **Redundancy:** You purchase a second router as a backup.
- **Fault Tolerance:** Your network automatically switches to the second router when the first router fails.
- **Scalability:** Your network can support 500 additional employees when the company grows.

### 5. How These Concepts Work Together
A well-designed enterprise network should consider all three concepts.
For example:
1. Redundancy provides backup network components.
2. Fault tolerance helps maintain services when components fail.
3. Scalability allows the network to support future growth.

These concepts help organisations build reliable and expandable networks.
